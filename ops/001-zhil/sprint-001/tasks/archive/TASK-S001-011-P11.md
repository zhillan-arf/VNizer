# TASK-S001-011 - Diagnose the FTT connection failure

## Objective

Find why VNizer rejects the FTT service at port 1812 despite its healthy `/health` response.
Make the failure message identify the failed check.

## Context

VNizer needs an FTT service that accepts image input for PDF pages.
The current check sends a small image to `/v1/chat/completions`.

## Plan

- Check the saved service URL and the live endpoint from the web container.
- Find the failing request and record its response without exposing credentials.
- Improve the connection error if it does not identify the cause.
- Run focused checks and record the result.

## Notes

The endpoint returned HTTP 200 for `/health` and `/v1/models` from the host.
The deployment guide states that this FTT service rejected images in an earlier check.
The saved FTT URL is `http://10.12.1.193:1812`. No FTT API key or model override is set.
The web container received HTTP 200 from `/v1/models` and HTTP 400 for an image request.
The image error said that the model allows zero images in one prompt.
Ports 1812 and 1813 both advertise `Qwen/Qwen3.8-27B-FP8`.
Both ports returned HTTP 200 for a short text request and HTTP 400 for an image request.
Both vLLM processes use `--language-model-only`.
VNizer now reports the image limit in its FTT connection error.
